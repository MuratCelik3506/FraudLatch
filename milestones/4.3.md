# Milestone 4.3 — Retry and Dead-Letter Policy

Status: Complete
Parent: 4
Depends on: 4.2
Owner: Repository maintainer

## Goal

Define and implement bounded retries that preserve messages while preventing poison events from blocking the worker.

## Why this matters

At-least-once processing is useful only when failures are visible and bounded. Retry metadata and a DLQ make transient outages recoverable and permanent failures diagnosable.

## Scope

- Three total attempts
- Retry schedule
- Transient/permanent error classification
- Retry stream/scheduled-entry handling
- DLQ stream
- Error metrics

## Out of scope

- Manual DLQ replay UI
- AWS SQS redrive policy
- Exactly-once guarantees

## Expected changes

Add retry policy module, Redis retry scheduling, DLQ publisher, and failure tests.

## Implementation checklist

- [x] Define attempt numbering as 1, 2, and 3 total attempts.
- [x] Use 1-second delay before attempt 2 and 5-second delay before attempt 3.
- [x] Classify dependency/timeout errors as transient.
- [x] Classify malformed/unsupported events as permanent.
- [x] Publish failed events to `fraudlatch:transactions:dlq:v1`.
- [x] Preserve original envelope, attempts, and error code.
- [x] Emit retry and DLQ metrics.

## Interfaces and contracts

Retryable processing does not acknowledge the event as completed. Once the third attempt fails, the original is safely dead-lettered and no longer blocks the main stream.

## Validation

Test immediate success, one transient failure, three transient failures, malformed envelope, and DLQ inspection.

## Acceptance criteria

- [x] Retry schedule is deterministic and tested.
- [x] Permanent errors do not loop indefinitely.
- [x] Third failure moves the message to DLQ.
- [x] No message is silently dropped.

## Failure and edge cases

If DLQ publication itself fails, retain the source message pending and emit a critical error; never acknowledge before DLQ durability is confirmed.

## Definition of done

Retry/DLQ behavior is bounded, observable, contract-tested, and ready for worker integration.
