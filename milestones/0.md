Status: In progress

## Base proposal

Start with [`00-proposal.md`](00-proposal.md). It is the dated scope and architecture baseline. It is intentionally not a status-board row. This file is the execution status board: it tracks dependencies, blockers, and completion of the numbered child milestones derived from the proposal.

## Project objective

FraudLatch is a local-first, Terraform-managed, event-driven fraud risk platform. The project will turn BankSim transactions into a deterministic replay stream, accept them through a FastAPI API, process risk asynchronously, and expose reliable results and operational signals.

The first delivery target is a reproducible local platform. AWS support is a later adapter and infrastructure phase because AWS access is not currently available.

## Current phase

The repository foundation, persistence/API contract, and transactional outbox write boundary are implemented. Queue adapters, dispatcher/worker processing, data replay, and infrastructure resources remain to be built.

## Architecture summary

```text
BankSim → Replayer → FastAPI
                    ↓
             PostgreSQL + outbox
                    ↓
             Outbox dispatcher
                    ↓
              Redis Streams
                    ↓
                Risk worker
                    ↓
             Risk assessment in DB
```

The system uses SQLAlchemy async with PostgreSQL, Redis Streams behind a queue port, a transactional outbox, at-least-once delivery, database-authoritative idempotency, three attempts with backoff, and a Redis-stream dead-letter queue.

## Current blockers

- AWS account access is not available; Milestone 12 remains deferred.
- Dependency Review requires a supported repository security configuration. It must not be made a required check until Dependency graph/Code Security support is confirmed.

## Completed decisions

- The canonical scope and architecture baseline is `milestones/00-proposal.md`; this file tracks execution status.
- Repository artifacts use English.
- Local runtime uses host Python with Terraform-managed services.
- Local queue uses Redis Streams behind `QueuePort`.
- Transactional outbox is part of the MVP.
- Database access uses SQLAlchemy async with asyncpg and Alembic migrations.
- External API has no authentication in the local MVP and documents that boundary.
- Risk scoring uses deterministic `rules-v1`; BankSim labels are evaluation-only.
- Delivery is at-least-once with three attempts, backoff and DLQ.
- Integration tests use Testcontainers.
- Docker image build and runtime packaging are separate from host-based development.
- BankSim acquisition is a manual, provenance-recorded step before validation.
