# Milestone 11.2 — Dependency Review and Security Settings

Status: Blocked
Parent: 11
Depends on: 11.1
Owner: Repository maintainer

## Goal

Enable only the GitHub security checks supported by the repository’s visibility and plan, without weakening the security signal.

## Why this matters

Dependency Review depends on GitHub’s Dependency graph and repository entitlements. A permanently failing unsupported workflow is noise; `continue-on-error` would hide real vulnerabilities.

## Scope

- Dependency graph prerequisite
- Dependabot alerts and updates
- Secret scanning and push protection
- Dependency Review workflow support check
- Branch ruleset integration
- `aws-dev` environment protection

## Out of scope

- Paid GitHub Advanced Security purchase
- Custom vulnerability database
- Automatic remediation of every alert

## Expected changes

Update GitHub repository settings and, only when supported, require `.github/workflows/dependency-review.yml`.

## Implementation checklist

- [ ] Confirm repository visibility and account/organization plan.
- [ ] Enable Dependency graph when available.
- [ ] Enable Dependabot alerts/security updates.
- [ ] Enable secret scanning/push protection when available.
- [ ] Re-run Dependency Review on a test pull request.
- [ ] Remove it from required checks if the repository remains unsupported.
- [ ] Keep `aws-dev` apply/destroy behind manual environment approval.

## Interfaces and contracts

The security workflow must fail on introduced vulnerable dependencies when GitHub supports the Dependency Review API. It must not use `continue-on-error` to mask unsupported or failed checks.

## Validation

Use the repository Security settings page, then run a pull request that changes `pyproject.toml` or the lock file.

## Acceptance criteria

- [ ] Supported repositories have a passing Dependency Review check.
- [ ] Unsupported repositories do not have a falsely required failing check.
- [ ] Dependabot configuration remains active.
- [ ] No AWS credentials are exposed to untrusted PR code.

## Failure and edge cases

Private personal repositories may not support Dependency Review without the required Code Security/GHAS entitlement. Record this as a repository limitation and keep the workflow non-required until the entitlement changes.

## Definition of done

Repository security checks are either active and enforceable or explicitly documented as unavailable.

## Follow-up

Revisit this milestone if repository visibility or GitHub plan changes.
