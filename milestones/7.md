# Milestone 7 — BankSim Data Pipeline

Status: Complete
Parent: —
Depends on: 1.3
Owner: Repository maintainer

## Goal

Turn the licensed, synthetic BankSim CSV into a validated, deterministic replay source without committing raw data.

## Why this matters

The dataset must behave like a reproducible event source, not like an opaque file copied into the application. Provenance, deterministic IDs, and label isolation protect the project’s credibility.

## Scope

- Dataset validation
- Canonical conversion
- Deterministic timestamps and IDs
- Parquet/manifest output
- HTTP transaction replay
- Offline result evaluation join

## Out of scope

- Online model training
- Data warehouse
- Dataset upload service
- Sending fraud labels to the scoring API

## Expected changes

Child milestones 7.1–7.3 define validation, conversion, and replay behavior.

## Implementation checklist

- [x] Complete 7.1.
- [x] Complete 7.2.
- [x] Complete 7.3.

## Interfaces and contracts

Raw input remains local under `data/raw`; processed output remains local under `data/processed`. Labels are retained only for offline evaluation and never passed as scoring features.

## Validation

Run preparation twice with the same seed and compare manifest, IDs, timestamps, and canonical rows.

## Acceptance criteria

- [x] Invalid input fails clearly.
- [x] Canonical output is deterministic.
- [x] Replay supports bounded rate and limits.
- [x] Evaluation can join labels to risk results offline.

## Failure and edge cases

Missing files, malformed amounts, null IDs, duplicate source rows, and partial replay failures must be visible and resumable without changing transaction IDs.

## Definition of done

At least 1,000 BankSim rows can be reproducibly prepared and replayed through the ingestion API.
