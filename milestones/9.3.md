# Milestone 9.3 — Monitoring Resources

Status: Not started
Parent: 9
Depends on: 8.1, 9.1
Owner: Repository maintainer

## Goal

Run Prometheus and Grafana through the same local Terraform network with mounted, versioned configuration.

## Why this matters

Monitoring must be reproducible alongside the application dependencies. Provisioned configuration makes dashboard behavior demonstrable and avoids undocumented manual setup.

## Scope

- Prometheus container
- Grafana container
- Configuration/dashboard mounts
- Network connectivity
- Health checks
- Access outputs

## Out of scope

- CloudWatch
- Alert notification integrations
- Application Docker images

## Expected changes

Add `monitoring.tf` and mount configuration from `monitoring/` into the containers.

## Implementation checklist

- [ ] Create Prometheus container on the shared network.
- [ ] Mount scrape configuration read-only.
- [ ] Create Grafana container with datasource provisioning.
- [ ] Mount dashboard definitions.
- [ ] Add health checks and local URLs.
- [ ] Keep default credentials out of tracked secret files.

## Interfaces and contracts

Prometheus must scrape API and worker `/metrics` endpoints. Grafana must use Prometheus as its provisioned datasource.

## Validation

Apply Terraform, inspect Prometheus target health, open Grafana, and verify dashboard provisioning from a clean state.

## Acceptance criteria

- [ ] Prometheus and Grafana are reachable after apply.
- [ ] Configuration changes are visible after controlled restart.
- [ ] Monitoring containers join the application network.
- [ ] Sensitive credentials are handled through local ignored inputs.

## Failure and edge cases

Missing configuration, unavailable targets, and Grafana startup races must be visible in health/status rather than reported as healthy.

## Definition of done

Local infrastructure includes an operational monitoring stack that can be destroyed and recreated from Terraform.

## Follow-up

Use the stack in 8.2 and 10.3.
