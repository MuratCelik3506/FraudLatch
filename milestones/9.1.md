# Milestone 9.1 — Terraform Provider, Network, and Volumes

Status: Complete
Parent: 9
Depends on: 1.3
Owner: Repository maintainer

## Goal

Create the local Terraform root, pin providers, and define the shared Docker network and persistent volumes.

## Why this matters

This establishes the resource graph and state behavior before service-specific configuration is added. It also makes provider upgrades deliberate and reviewable.

## Scope

- Terraform version constraint
- Docker provider constraint
- `.terraform.lock.hcl`
- `docker_network`
- PostgreSQL/Redis/monitoring volumes
- Variables and outputs

## Out of scope

- Containers
- Remote S3 state
- AWS resources

## Expected changes

Add `infra/terraform/local` root files: `terraform.tf`, `providers.tf`, `variables.tf`, `network.tf`, `outputs.tf`, and example variables.

## Implementation checklist

- [x] Declare tested Terraform/provider version ranges.
- [ ] Run `terraform init` and commit the lock file.
- [x] Define a named network.
- [x] Define named persistent volumes.
- [x] Mark sensitive outputs appropriately.
- [x] Add project/environment tags or labels where supported.

## Interfaces and contracts

All local containers join the same named network. Application connection URLs are exposed as outputs without printing passwords.

## Validation

Run formatting, validation, plan, state list, and destroy on a clean Docker daemon.

## Acceptance criteria

- [ ] Provider versions are locked.
- [ ] Network and volumes appear in Terraform state.
- [ ] Sensitive values are not exposed in normal output.
- [ ] Destroy removes only resources in this local root.

## Failure and edge cases

Provider initialization failure, Docker daemon unavailable, and existing-name conflicts must produce actionable errors.

## Definition of done

The local Terraform graph is valid and ready for PostgreSQL/Redis resources.

## Follow-up

Add stateful service containers in 9.2.
