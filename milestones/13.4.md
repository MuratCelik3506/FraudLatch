# Milestone 13.4 — Blue/Green Deployment

Status: Deferred
Parent: 13
Depends on: 12.4
Owner: Repository maintainer

## Goal

Demonstrate a reversible API deployment strategy with health-gated traffic shifting.

## Why this matters

Rollback safety is a production concern, but it requires a working ECS/ALB baseline and a clear migration compatibility policy.

## Scope

- Two ECS task revisions/environments
- ALB target switching
- Health-gated promotion
- Rollback procedure
- Deployment evidence

## Out of scope

- Database-breaking migrations without compatibility planning
- Multi-region failover
- Automatic production release

## Expected changes

Add deployment strategy configuration and a runbook for promote/rollback.

## Implementation checklist

- [ ] Define compatible API/database migration sequence.
- [ ] Deploy candidate revision.
- [ ] Validate health and smoke checks.
- [ ] Shift traffic deliberately.
- [ ] Record rollback trigger and execute rollback test.

## Interfaces and contracts

Both revisions must serve the same API and event schema during the transition.

## Validation

Deploy a known-good and intentionally unhealthy candidate, verify promotion/rollback behavior.

## Acceptance criteria

- [ ] Unhealthy candidate receives no production traffic.
- [ ] Rollback restores the previous healthy revision.
- [ ] In-flight events remain processable.

## Failure and edge cases

ALB health race, incompatible migration, failed image pull, and half-shifted traffic require documented recovery.

## Definition of done

A reversible, health-gated deployment demonstration is repeatable.

## Follow-up

Keep deployment automation manual until operational confidence is established.
