# Milestone 5 — Risk Engine

Status: Not started
Parent: —
Depends on: 1.3
Owner: Repository maintainer

## Goal

Produce explainable, deterministic risk decisions without coupling the engine to HTTP, Redis, PostgreSQL, or BankSim labels.

## Why this matters

The project’s primary showcase is reliable event processing and infrastructure. A pure rules engine provides explainability, reproducibility, and a stable seam for a future ML baseline.

## Scope

- `rules-v1`
- Configured thresholds
- Stable reason codes
- Score and risk-level mapping
- Customer/merchant velocity context

## Out of scope

- ML training
- Online retraining
- Fraud-label feature leakage
- Feature store

## Expected changes

Child milestones 5.1–5.3 define pure rules, Redis-backed velocity context, and customer amount deviation context.

## Implementation checklist

- [ ] Complete 5.1.
- [ ] Complete 5.2.
- [ ] Complete 5.3.
- [ ] Prove labels never reach the scoring function.

## Interfaces and contracts

```python
assess(transaction, context) -> RiskDecision
```

The function is deterministic and side-effect-free.

## Validation

Use table-driven rule tests and repeated-run determinism tests.

## Acceptance criteria

- [ ] Risk score is in `[0, 1]`.
- [ ] Risk level and reason codes are stable.
- [ ] Engine version is persisted with every result.
- [ ] Same input/context always produces the same decision.

## Failure and edge cases

Missing optional context must produce a documented cold-start behavior, not an arbitrary score or exception.

## Definition of done

Rules, velocity context, and amount deviation context are unit-tested and ready for worker use.

## Follow-up

Integrate the engine into the worker in Milestone 6.
