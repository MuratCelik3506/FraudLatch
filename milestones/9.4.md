# Milestone 9.4 — Application Images and Container Runtime

Status: Complete
Parent: 9
Depends on: 2, 6, 9.2
Owner: Repository maintainer

## Goal

Package the API, dispatcher, and worker as reproducible Docker images for release/demo execution while preserving the fast host-Python development mode.

## Why this matters

Docker images are part of the proposal MVP and are required by the future ECR/ECS deployment. Separating image packaging from local service lifecycle avoids forcing rebuilds during every code edit.

## Scope

- API image
- Dispatcher image
- Worker image
- Shared dependency/install strategy
- Non-root runtime user
- Health checks and signal handling
- `make docker-build`

## Out of scope

- Image publishing to ECR; Milestone 12.4.
- Kubernetes
- Production image signing pipeline

## Expected changes

Add Dockerfiles under `docker/`, build context documentation, `.dockerignore`, and Makefile targets. Add a dispatcher Dockerfile or a documented shared image entrypoint.

## Implementation checklist

- [x] Build API image with a minimal runtime layer.
- [x] Build worker image with the same dependency lock.
- [x] Build dispatcher image or define a safe role-based entrypoint.
- [x] Run as non-root.
- [x] Propagate SIGTERM for graceful shutdown.
- [x] Add health checks appropriate to each process.
- [x] Keep secrets out of image layers.
- [x] Verify `make docker-build` locally and in CI.

## Interfaces and contracts

Images receive configuration through environment variables and use the same API, database, Redis, queue, and event contracts as host processes.

## Validation

Build all images from a clean context, inspect layers for secrets, run containers on the Terraform network, and execute the submit-to-result smoke flow.

## Acceptance criteria

- [ ] API, dispatcher, and worker images build reproducibly.
- [ ] Images do not contain `.env`, raw data, Terraform state, or credentials.
- [ ] Containers start with documented commands.
- [ ] Graceful shutdown and health checks work.
- [ ] CI builds images when their Dockerfiles exist.

## Failure and edge cases

Missing dependencies, wrong architecture, port conflicts, invalid environment values, and terminated containers must produce clear logs and non-zero exits.

## Definition of done

FraudLatch has a release/demo container runtime in addition to host-based development, and the images are ready for future ECR publishing.

## Follow-up

Use these images in 12.4 ECS deployment.
