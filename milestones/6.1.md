# Milestone 6.1 — Worker Lifecycle and Idempotency

Status: Complete
Parent: 6
Depends on: 4.2, 4.3, 5.2
Owner: Repository maintainer

## Goal

Implement a restartable consumer that processes messages at least once while using the database as the authoritative idempotency boundary.

## Why this matters

Queue delivery and process execution are not exactly once. Explicit lifecycle and idempotency behavior prevents duplicate events or crashes from producing duplicate risk decisions.

## Scope

- Consumer group loop
- Graceful SIGTERM shutdown
- Event validation
- Transaction lookup
- Existing result detection
- Retry/DLQ policy integration
- Redis idempotency optimization

## Out of scope

- Risk result schema details; see 6.2.
- Horizontal autoscaling
- Exactly-once claims

## Expected changes

Add worker entrypoint, processor service, lifecycle controller, idempotency checks, and worker tests.

## Implementation checklist

- [x] Read messages through `QueuePort`.
- [x] Validate event type and schema version.
- [x] Skip work when a completed result already exists.
- [x] Mark processing before risk calculation.
- [x] Commit result before `ack`.
- [x] Stop intake on SIGTERM and finish the current message.
- [x] Route classified failures to retry/DLQ.

## Interfaces and contracts

The worker’s durable completion signal is a committed `risk_assessments` row. Redis idempotency keys can accelerate duplicate checks but cannot replace the database constraint/state.

## Validation

Test duplicate events, worker restart with pending messages, commit failure before ack, and graceful shutdown.

## Acceptance criteria

- [x] A completed transaction event is safe to deliver repeatedly.
- [x] No message is acknowledged before result commit.
- [x] Worker restart reclaims unacknowledged work.
- [x] Retry and DLQ policy receives the correct attempt/error metadata.

## Failure and edge cases

An event for a missing transaction is permanent failure. A database or Redis dependency failure is retryable. Shutdown must not acknowledge a message that was interrupted before commit.

## Definition of done

Worker lifecycle and idempotency tests pass against the queue contract.
