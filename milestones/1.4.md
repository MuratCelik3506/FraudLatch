# Milestone 1.4 — Developer Command Contract

Status: Complete
Parent: 1
Depends on: 1.3
Owner: Repository maintainer

## Goal

Define one documented command interface for setup, quality checks, local infrastructure, data preparation, services, replay, and cleanup.

## Why this matters

A production-style repository should be easy to operate without remembering implementation-specific commands. A stable Makefile contract also gives CI and onboarding documentation one shared vocabulary.

## Scope

- `make setup`
- `make quality`
- `make infra-init`, `make infra-plan`, `make infra-up`, `make infra-down`
- `make data-check`, `make data-prepare`
- `make api`, `make dispatcher`, `make worker`, `make replay`
- `make docker-build`
- `make test`, `make lint`, `make format`

## Out of scope

- AWS apply/destroy until Milestone 12.
- Hiding dangerous operations behind ambiguous command names.
- Automatic BankSim download.

## Expected changes

Extend `Makefile` only when the corresponding implementation exists and document command prerequisites in `README.md`.

## Implementation checklist

- [x] Define the initial command names and required environment variables.
- [x] Make service commands fail clearly when dependencies are unavailable.
- [x] Add data commands that never download licensed data automatically.
- [x] Add explicit local infrastructure up/down commands.
- [x] Add dispatcher command alongside API and worker.
- [x] Add Docker build command for release/demo images.
- [x] Keep destructive commands (`infra-down`, destroy) explicit.

## Interfaces and contracts

Commands must be safe to run from repository root and must use `.env`/documented local configuration. `make data-check` validates the manually acquired file; it does not fetch it.

## Validation

Run each command from a clean checkout, with and without required dependencies, and verify error messages and exit codes.

## Acceptance criteria

- [x] A contributor can follow README commands without guessing process entrypoints.
- [x] Data acquisition is a separate manual step from data validation.
- [x] API, dispatcher, worker, and replay commands are named consistently.
- [x] Cleanup commands are explicit and documented.

## Failure and edge cases

Commands must not silently create cloud resources, fetch credentials, overwrite raw data, or continue after a required dependency fails.

## Definition of done

The repository exposes a complete, documented local command contract used by developers, smoke tests, and CI.

## Follow-up

Keep command changes synchronized with milestones 7, 9, and 11.
