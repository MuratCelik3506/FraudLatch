## Goal

Make the proposal and milestone roadmap consistent with the `FraudLatch` name, current paths, and English-only repository policy.

## Why this matters

The proposal is the architectural reference. If it contains stale names, Turkish-only sections, or paths that no longer exist, implementers can build incompatible components and readers cannot trust it as a project contract.

## Scope

- Use `FraudLatch` consistently.
- Keep the proposal filename and repository paths current.
- Link the proposal to `milestones/0.md`.
- Translate or normalize planning prose into English without changing technical intent.
- Preserve dataset provenance and license statements.

## Out of scope

- Changing the approved architecture.
- Implementing application or infrastructure code.
- Adding new features not represented in the proposal.

## Expected changes

Maintain the canonical proposal in `milestones/00-proposal.md` and keep `fraudlatch_project_proposal.md` as a compatibility entry point.
