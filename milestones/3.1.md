# Milestone 3.1 — Outbox Schema and Atomic Write

Status: Not started
Parent: 3
Depends on: 2.1, 2.2
Owner: Repository maintainer

## Goal

Add a durable event outbox and write it atomically with every accepted transaction.

## Why this matters

The outbox is the reliability boundary between synchronous ingestion and asynchronous processing. It preserves intent even when Redis, the dispatcher, or the process is unavailable.

## Scope

- `outbox_events` table
- JSONB versioned payload
- Pending/published/failed state
- Attempts and retry scheduling fields
- Transaction service atomic write
- Event uniqueness policy

## Out of scope

- Redis publishing implementation
- Worker consumption
- Dead-letter handling for queue messages

## Expected changes

Add an Alembic migration, SQLAlchemy model, outbox repository, and transaction-service transaction boundary.

## Implementation checklist

- [ ] Add unique `event_id`, `aggregate_id`, `event_type`, and `schema_version`.
- [ ] Store `occurred_at` and `created_at` as timezone-aware UTC timestamps.
- [ ] Store `payload` as JSONB and timestamps as UTC.
- [ ] Add `status`, `attempts`, `next_attempt_at`, `published_at`, and `last_error`.
- [ ] Add uniqueness for one initial event per transaction/schema version.
- [ ] Insert transaction and outbox row in one session transaction.
- [ ] Add commit-failure and rollback tests.

## Interfaces and contracts

The initial event uses `event_type=transaction.received`, `schema_version=1`, `aggregate_id=transaction_id`, and `status=pending`.

## Validation

Test successful commit, database rollback, duplicate API retry, and queue-unavailable API operation.

## Acceptance criteria

- [ ] Transaction and outbox row commit together.
- [ ] Neither can exist without the other after a failed transaction.
- [ ] Duplicate request does not create a second outbox event.
- [ ] Failed/pending rows remain queryable for dispatcher recovery.

## Failure and edge cases

Unique-constraint races must return the established idempotent/conflict API behavior. Payload serialization errors must roll back the transaction.

## Definition of done

Migration and service tests prove the outbox invariant under success, rollback, duplicate, and serialization failure.

## Follow-up

Implement polling and Redis publication in 3.2.
