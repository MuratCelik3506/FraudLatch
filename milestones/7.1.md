# Milestone 7.1 — Dataset Acquisition and Validation

Status: Not started
Parent: 7
Depends on: 1.3
Owner: Repository maintainer

## Goal

Obtain the BankSim source through a documented manual download, place it in the expected local path, and validate it before any transformation or replay occurs.

## Why this matters

Failing early on schema or data-quality errors prevents corrupt transactions from entering PostgreSQL and makes the preparation process auditable.

## Scope

- Required column validation
- Null and type validation
- Duplicate checks
- File hash
- Missing file instructions
- License/provenance metadata
- Manual acquisition workflow and local filename contract

## Out of scope

- Risk scoring
- Data cleaning that changes source meaning
- Raw dataset storage in Git

## Expected changes

Add `scripts/validate_dataset.py`, validation result models, command documentation, and a manual acquisition guide.

## Implementation checklist

- [ ] Read the BankSim dataset page and accept its `CC BY-NC-SA 4.0` terms for this non-commercial project.
- [ ] Download the source CSV manually from the documented Kaggle source; do not put credentials in the repository or CI.
- [ ] Extract an archive locally when necessary and place only `bs140513_032310.csv` at `data/raw/bs140513_032310.csv`.
- [ ] Run `make data-check` before preprocessing.
- [ ] Require `step`, `customer`, `merchant`, `category`, `amount`, and `fraud`.
- [ ] Validate numeric amount and binary fraud label.
- [ ] Detect null IDs/category/amount.
- [ ] Report duplicate source rows without silently dropping them.
- [ ] Compute SHA-256 file hash.
- [ ] Print actionable missing-file guidance.
- [ ] Record source URL and license in the manifest.

## Interfaces and contracts

The acquisition step is manual and local. The source is the BankSim Kaggle dataset at `https://www.kaggle.com/datasets/ealaxi/banksim1`. Validation returns a non-zero exit code on invalid input and a concise report containing row count, fraud count, and source hash on success.

## Validation

Run valid fixture, missing file, missing column, null field, invalid amount, invalid label, and duplicate fixture tests.

## Acceptance criteria

- [ ] Required BankSim schema is enforced.
- [ ] A contributor can obtain the file and place it at the documented path without guessing.
- [ ] Invalid data cannot reach canonical conversion.
- [ ] Raw file is never copied into tracked repository paths.
- [ ] Validation output is deterministic except for process timing.

## Failure and edge cases

Duplicate source rows are reported and preserved for an explicit conversion decision; they are not silently deduplicated by row content.

## Definition of done

Dataset validation produces actionable failures and a provenance-aware success report.

## Follow-up

Convert only validated input in 7.2. The raw CSV remains outside Git and is never downloaded automatically by CI.
