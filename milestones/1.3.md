# Milestone 1.3 — Python Project Baseline

Status: Complete
Parent: 1
Depends on: 1.1
Owner: Repository maintainer

## Goal

Provide a clean Python package, dependency declaration, quality gate, and developer command interface before application code is added.

## Why this matters

Every later service depends on consistent imports, formatting, typing, testing, and local setup. Establishing these contracts first prevents service code from defining incompatible conventions.

## Scope

- Python 3.12 package baseline
- Ruff formatting and linting
- Strict mypy configuration
- Pytest configuration and smoke test
- Makefile setup/quality commands

## Out of scope

- FastAPI, SQLAlchemy, Redis, or AWS dependencies
- Business logic
- Container images

## Expected changes

`pyproject.toml`, `fraudlatch/__init__.py`, `tests/unit/test_smoke.py`, and `Makefile` define this baseline.

## Implementation checklist

- [x] Declare the package as `fraudlatch`.
- [x] Declare Python and development-tool constraints.
- [x] Configure Ruff, mypy, and pytest.
- [x] Add `make setup`, `make quality`, and Terraform helper targets.
- [x] Verify the commands with Python 3.12, Ruff, and Terraform installed.

## Interfaces and contracts

```text
make setup
make quality
make format
make lint
make typecheck
make test
```

The package must be importable without starting infrastructure.

## Validation

```bash
PYTHON=python3.12 make setup
make quality
make terraform-fmt
make terraform-validate
ruff format --check .
ruff check .
mypy fraudlatch
```

The setup target creates `.venv` before installing development dependencies;
the quality targets invoke tools from that environment directly.

## Acceptance criteria

- [x] A clean Python 3.12 environment can install the project.
- [x] `make quality` passes without external services.
- [x] The package smoke test passes.
- [x] No runtime dependency is added without a documented purpose; runtime dependencies remain empty until Milestone 2.1.

## Failure and edge cases

Tooling failures must fail CI. Tests that need PostgreSQL or Redis belong to later integration-test milestones and must not be hidden inside the smoke test.

## Definition of done

The baseline commands pass in local development and CI, and future services can import `fraudlatch` without path hacks.

## Follow-up

Add production dependencies only when implementing Milestone 2.1 and record each group in the relevant milestone.
