# Milestone 9 — Local Terraform Infrastructure

Status: Not started
Parent: —
Depends on: 1.3
Owner: Repository maintainer

## Goal

Make local stateful dependencies and monitoring reproducible through Terraform’s Docker provider.

## Why this matters

Terraform is a primary project objective, not a deployment afterthought. A single local graph demonstrates providers, resources, state, dependencies, volumes, outputs, and destroy behavior before AWS is available.

## Scope

- Docker provider
- Network and volumes
- PostgreSQL and Redis containers
- Prometheus and Grafana containers
- Local variables, outputs, and health checks

## Out of scope

- AWS provider
- ECS/RDS/ElastiCache
- Application containers during host-development mode

## Expected changes

Child milestones 9.1–9.4 define the Terraform root, service resources, and application image packaging.

## Implementation checklist

- [ ] Complete 9.1.
- [ ] Complete 9.2.
- [ ] Complete 9.3.
- [ ] Complete 9.4.
- [ ] Verify apply, drift detection, and destroy.

## Interfaces and contracts

Terraform manages local service lifecycle; API, dispatcher, worker, and replayer run on the host during development.

## Validation

```bash
terraform init
terraform fmt -check -recursive
terraform validate
terraform plan
terraform apply
terraform destroy
```

## Acceptance criteria

- [ ] One apply creates all local dependencies.
- [ ] Volumes preserve state across container recreation.
- [ ] Destroy removes managed resources.
- [ ] No secret-bearing values are committed.

## Failure and edge cases

Missing Docker daemon, occupied ports, invalid credentials, and partial apply must fail visibly with recoverable state.

## Definition of done

Local infrastructure is reproducible, inspectable with Terraform state, and safe to destroy.

## Follow-up

Use the resulting services for local smoke runs and monitoring validation; use 9.4 for the release/demo container runtime.
