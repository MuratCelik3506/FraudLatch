# Milestone 12.3 — AWS Network, IAM, and Secrets

Status: Deferred
Parent: 12
Depends on: 12.2
Owner: Repository maintainer

## Goal

Provision a least-privilege, private AWS foundation for ECS, RDS, Redis, and SQS.

## Why this matters

Network reachability and IAM boundaries determine whether the cloud deployment is secure and operable. These decisions must be explicit before compute resources are launched.

## Scope

- VPC
- Public/private subnets
- Route tables and gateways
- Security groups
- IAM task/execution roles
- Secrets Manager
- Required resource tags

## Out of scope

- ECS services
- Public database/Redis endpoints
- Wildcard IAM permissions
- Multi-region networking

## Expected changes

Add reusable Terraform modules for network, IAM, and secrets plus the `aws-dev` environment wiring.

## Implementation checklist

- [ ] Define public ALB and private data/worker subnets.
- [ ] Restrict security-group ingress by service dependency.
- [ ] Create an API role with database/Redis connectivity and only the required secrets permissions; it must not publish to SQS.
- [ ] Create a dispatcher role with outbox database access, `sqs:SendMessage`, and only the required secrets permissions.
- [ ] Create worker role with receive/delete/change-visibility/secrets permissions.
- [ ] Store database/Redis credentials in Secrets Manager.
- [ ] Add project/environment/owner/managed-by tags.
- [ ] Add cost TTL metadata or budget controls.

## Interfaces and contracts

API, dispatcher, and worker receive only the secrets and AWS actions they need. The API never receives `sqs:SendMessage`; only the dispatcher publishes to SQS. RDS and ElastiCache are reachable only from approved task security groups.

## Validation

Use Terraform plan review, IAM policy simulation where available, security-group inspection, and connectivity tests from disposable tasks.

## Acceptance criteria

- [ ] Database and Redis are not publicly reachable.
- [ ] API, dispatcher, and worker roles have no wildcard `Action=*`/`Resource=*` access.
- [ ] API has no `sqs:SendMessage` permission; dispatcher has only scoped publish access.
- [ ] Secrets are not present in Terraform outputs or images.
- [ ] Required tags appear on billable resources.

## Failure and edge cases

DNS/routing failure, denied IAM action, secret rotation mismatch, subnet exhaustion, and security-group misconfiguration must be diagnosable from logs and plan output.

## Definition of done

AWS data-plane networking and identity boundaries are secure and ready for ECS/persistence resources.

## Follow-up

Deploy ECR/ECS/RDS/ElastiCache and CloudWatch in 12.4.
