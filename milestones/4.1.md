# Milestone 4.1 — Queue Port and Versioned Event Envelope

Status: Complete
Parent: 4
Depends on: 1.3
Owner: Repository maintainer

## Goal

Define the stable message interface shared by the dispatcher, Redis adapter, worker, and future SQS adapter.

## Why this matters

An explicit contract prevents infrastructure-specific message formats from leaking into domain code and makes schema evolution reviewable.

## Scope

- Generic Pydantic `EventEnvelope[T]`
- `QueuePort`, `QueueMessage`, and `MessageHandle`
- Event validation and schema-version policy
- Serialization/deserialization tests

## Out of scope

- Redis implementation
- Retry timing
- Risk result schema

## Expected changes

Add contract models under `fraudlatch/contracts` and queue interfaces under `fraudlatch/queue`.

## Implementation checklist

- [x] Implement required envelope fields.
- [x] Define `transaction.received` payload version 1.
- [x] Make timestamps timezone-aware.
- [x] Reject unsupported schema versions explicitly.
- [x] Define message acknowledgement and retry method signatures.
- [x] Add round-trip JSON tests.

## Interfaces and contracts

Required envelope fields are `event_id`, `event_type`, `schema_version`, `occurred_at`, `aggregate_id`, and `payload`.

## Validation

Test missing fields, invalid UUID/time, unsupported versions, extra-fields policy, and JSON round trips.

## Acceptance criteria

- [x] A valid event serializes and deserializes without information loss.
- [x] Queue clients depend only on `QueuePort`.
- [x] Invalid envelopes produce stable error codes.
- [x] Event IDs remain stable across retries.

## Failure and edge cases

Do not silently coerce naive timestamps or unknown schema versions. Preserve the original serialized payload for dead-letter inspection.

## Definition of done

The queue contract is documented, typed, tested, and ready for two independent adapters.

Implement Redis Streams behavior in 4.2.
