# Milestone 10 — Testing Strategy

Status: Not started
Parent: —
Depends on: 2–9
Owner: Repository maintainer

## Goal

Prove domain contracts, database/queue integrations, and end-to-end failure behavior with fast and isolated tests.

## Why this matters

The project’s core claims—idempotency, at-least-once processing, deterministic replay, and no silent data loss—must be executable acceptance criteria, not only documentation.

## Scope

- Unit and contract tests
- Testcontainers integration tests
- Failure scenarios
- Local submit/process/query smoke test

## Out of scope

- Benchmarking at production scale
- AWS deployment testing
- ML quality benchmarking

## Expected changes

Child milestones 10.1–10.3 define test categories and execution contracts.

## Implementation checklist

- [ ] Complete 10.1.
- [ ] Complete 10.2.
- [ ] Complete 10.3.
- [ ] Include all stable test commands in CI.

## Interfaces and contracts

Unit tests require no external services. Integration tests create disposable PostgreSQL and Redis. E2E tests use the same API/worker contracts as local development.

## Validation

```bash
pytest
pytest -m integration
```

## Acceptance criteria

- [ ] Pure domain behavior is fast and deterministic.
- [ ] Database/Redis behavior is isolated per test run.
- [ ] Failure scenarios prove retry, DLQ, and idempotency behavior.
- [ ] Full local flow is executable from a clean setup.

## Failure and edge cases

Tests must fail on contract regressions; skipped integration tests must be explicit and never silently counted as coverage of unavailable services.

## Definition of done

All critical reliability claims have automated tests and CI commands.

## Follow-up

Use test outcomes to set required checks in Milestone 11.
