# Milestone 12.1 — SQS Adapter

Status: Deferred
Parent: 12
Depends on: 4.1, 4.3
Owner: Repository maintainer

## Goal

Implement AWS SQS behind the existing `QueuePort` while preserving event, retry, acknowledgement, and DLQ semantics.

## Why this matters

The local Redis implementation should not force a second worker implementation. Adapter parity demonstrates that domain logic is infrastructure-independent.

## Scope

- SQS send/receive/delete
- Visibility timeout
- Message attributes
- Redrive policy
- SQS DLQ
- Contract tests

## Out of scope

- FIFO queue optimization
- Cross-region queues
- Autoscaling

## Expected changes

Add SQS adapter, IAM permission requirements, Terraform queue resources, and adapter contract tests.

## Implementation checklist

- [ ] Map event metadata to SQS message attributes.
- [ ] Map visibility timeout to processing lease.
- [ ] Delete only after database commit.
- [ ] Configure redrive policy and DLQ.
- [ ] Verify duplicate delivery behavior.
- [ ] Pass all queue-port contract tests.

## Interfaces and contracts

SQS must provide at-least-once delivery and preserve `event_id`, `event_type`, `schema_version`, and `aggregate_id`.

## Validation

Plan and apply a disposable AWS dev queue, run submit-to-result, force worker failure, inspect retry and DLQ behavior, then destroy.

## Acceptance criteria

- [ ] Worker code has no SQS-specific branches.
- [ ] Visibility timeout exceeds the expected processing lease.
- [ ] Redrive policy moves poison messages to DLQ.
- [ ] Duplicate SQS delivery is idempotent.

## Failure and edge cases

Visibility timeout expiry, delete failure, IAM denial, malformed attributes, and DLQ redrive failure must be observable and retry-safe.

## Definition of done

SQS passes the same behavioral contract as Redis Streams for the worker and dispatcher.

## Follow-up

Provision remote state before larger AWS infrastructure in 12.2.
