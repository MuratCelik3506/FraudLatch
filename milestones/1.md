# Milestone 1 — Repository and Application Foundation

Status: In progress
Parent: —
Depends on: —
Owner: Repository maintainer

## Goal

Create the shared repository, documentation, and Python conventions required for every later milestone.

## Why this matters

The foundation prevents architecture work from being mixed with avoidable naming, tooling, packaging, and review-process decisions. It also makes the project reproducible for contributors and future portfolio reviewers.

## Scope

- Repository language and contribution conventions
- Proposal normalization
- Python package, quality tools, tests, and Makefile contract

## Out of scope

- API behavior
- Database schema
- Terraform resources
- Cloud deployment

## Expected changes

The child documents 1.1, 1.2, 1.3, and 1.4 define the work. No runtime feature is part of this parent milestone.

## Implementation checklist

- [x] Document English-only repository conventions.
- [x] Normalize the proposal and link it to the roadmap.
- [ ] Define and verify the developer command contract.
- [ ] Verify Python setup and quality commands on a clean environment.

## Interfaces and contracts

The repository contract consists of `pyproject.toml`, `Makefile`, `.editorconfig`, `.gitignore`, English documentation, and a package importable as `fraudlatch`.

## Validation

```bash
make setup
make quality
git diff --check
```

## Acceptance criteria

- [ ] A new contributor can identify the language, setup, and contribution rules.
- [x] Proposal paths and names match the current repository.
- [ ] Python quality and smoke-test commands are reproducible.

## Failure and edge cases

Missing optional tools must fail with a clear setup instruction rather than silently skipping quality checks.

## Definition of done

Child milestones 1.1, 1.2, 1.3, and 1.4 satisfy their acceptance criteria and `milestones/0.md` is updated.

## Follow-up

Start Milestone 2.1 after this foundation is complete.
