# Milestone 12.2 — Remote State Bootstrap

Status: Deferred
Parent: 12
Depends on: 9.1
Owner: Repository maintainer

## Goal

Create a protected S3 backend for AWS Terraform state using a separate bootstrap root.

## Why this matters

Remote state enables collaboration and locking while separating state lifecycle from the application environment that depends on it.

## Scope

- Bootstrap Terraform root
- S3 bucket
- Versioning
- Encryption
- Public-access block
- S3 lockfile
- Backend migration documentation

## Out of scope

- DynamoDB locking
- Application infrastructure
- State values in Git

## Expected changes

Add `infra/terraform/bootstrap/state`, backend configuration, and secure migration/runbook documentation.

## Implementation checklist

- [ ] Create bootstrap root with local/bootstrap state handling.
- [ ] Enable bucket versioning.
- [ ] Enable encryption.
- [ ] Block public access.
- [ ] Enable S3 lockfile-based locking.
- [ ] Add retention/protection against accidental destroy.
- [ ] Initialize AWS dev root against the remote backend.

## Interfaces and contracts

The AWS environment backend is separate from the bootstrap backend. State bucket name, region, and key are explicit configuration and never secret values.

## Validation

Run bootstrap plan/apply, inspect bucket settings, initialize AWS environment, verify lock acquisition, and test a controlled state recovery.

## Acceptance criteria

- [ ] State is encrypted, versioned, private, and lockable.
- [ ] Application root uses remote state.
- [ ] Bootstrap instructions work from a clean operator environment.
- [ ] State bucket cannot be casually destroyed by the application root.

## Failure and edge cases

Concurrent plan/apply, backend migration failure, unavailable bucket, and stale lock must have documented recovery steps.

## Definition of done

AWS Terraform state is protected and independently bootstrapped.

## Follow-up

Build private networking, IAM, and secrets in 12.3.
