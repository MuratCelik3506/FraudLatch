# Milestone 5.1 — Deterministic rules-v1

Status: Not started
Parent: 5
Depends on: 1.3
Owner: Repository maintainer

## Goal

Implement the first explainable rules engine with versioned thresholds and stable outputs.

## Why this matters

Stable reason codes make a fraud decision auditable and testable. Configuration-driven thresholds make behavior reviewable and allow later tuning without changing the engine interface.

## Scope

- `HIGH_AMOUNT`
- `CUSTOMER_VELOCITY`
- `MERCHANT_VELOCITY`
- `CATEGORY_RISK`
- Score normalization
- Risk-level thresholds
- `rules-v1` version

## Out of scope

- Training a model
- Reading labels during scoring
- Runtime customer historical distribution lookup; amount deviation is covered by 5.3.

## Expected changes

Add risk domain models, rules configuration, pure evaluation functions, and unit tests.

## Implementation checklist

- [ ] Define configured global/category amount thresholds.
- [ ] Define customer and merchant velocity thresholds.
- [ ] Define category risk weights without runtime label access.
- [ ] Define deterministic reason ordering.
- [ ] Normalize combined rule contributions to `[0, 1]`.
- [ ] Map score to LOW/MEDIUM/HIGH.
- [ ] Persist `engine_version = rules-v1` in result models.

## Interfaces and contracts

```text
LOW: score < 0.40
MEDIUM: 0.40 <= score < 0.70
HIGH: score >= 0.70
```

`RiskDecision` contains `risk_score`, `risk_level`, `reasons`, and `engine_version`.

## Validation

Test each rule independently, rule combinations, boundary scores, missing context, and reason ordering.

## Acceptance criteria

- [ ] Pure rules do not access database, Redis, HTTP, or labels.
- [ ] Identical inputs yield identical output.
- [ ] Every active rule has a reason code.
- [ ] Score and level boundaries are tested.

## Failure and edge cases

Invalid configuration must fail at startup/configuration load. Unknown reason codes must not be emitted.

## Definition of done

`rules-v1` is deterministic, explainable, configurable, and fully unit-tested.

Provide velocity context from Redis in 5.2.
