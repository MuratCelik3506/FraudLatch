# Milestone 7.2 — Canonical Conversion

Status: Complete
Parent: 7
Depends on: 7.1
Owner: Repository maintainer

## Goal

Convert BankSim rows into the internal transaction schema with stable IDs, synthetic time, and explicit source metadata.

## Why this matters

The application contract should not depend on Kaggle column names. Canonical conversion gives the API a stable domain model and makes replays reproducible across environments.

## Scope

- Deterministic transaction ID generation
- Canonical field mapping
- Synthetic `event_time`
- Source versus synthetic enrichment separation
- Parquet output
- Manifest output

## Out of scope

- Calling the API
- Calculating risk
- Using fraud labels in features

## Expected changes

Add `scripts/prepare_banksim.py`, canonical models, conversion functions, and manifest writer.

## Implementation checklist

- [x] Map source customer/merchant/category/amount/step fields.
- [x] Generate stable ID from seed and source row identity.
- [x] Map `event_time` to fixed epoch plus `step` days.
- [x] Preserve `source_step` and source name.
- [x] Keep labels in evaluation metadata only.
- [x] Write Parquet and deterministic manifest.
- [x] Support an explicit seed argument.

## Interfaces and contracts

```text
event_time = 2026-01-01T00:00:00Z + source_step days
```

Same input and seed must produce the same canonical transaction ID, event time, and source fields.

## Validation

Compare two outputs generated from the same fixture and seed byte-for-byte where the output format permits, and row-for-row otherwise.

## Acceptance criteria

- [x] Canonical output has all API-required fields.
- [x] Same input/seed yields identical output.
- [x] Synthetic enrichment is clearly separated from BankSim source fields.
- [x] Ground-truth labels are not part of the scoring payload.

## Failure and edge cases

Unknown category, negative amount, invalid step, and ID collision must fail conversion with a row reference rather than producing a partial silent result.

## Definition of done

Validated BankSim data produces deterministic Parquet and a provenance manifest suitable for replay.

## Follow-up

Send canonical rows through the API in 7.3.
