# Milestone 5.2 — Velocity State

Status: Complete
Parent: 5
Depends on: 4.2, 5.1
Owner: Repository maintainer

## Goal

Provide five-minute customer and merchant transaction context to the risk engine using Redis Sorted Sets.

## Why this matters

Burst behavior is a useful fraud signal and demonstrates a real operational use for Redis. Keeping it outside the pure engine preserves testability and infrastructure separation.

## Scope

- Customer velocity Sorted Sets
- Merchant velocity Sorted Sets
- Event-time windowing
- Expired entry cleanup
- Cold-start behavior
- Redis failure classification

## Out of scope

- Long-term feature storage
- Label-derived live features
- Redis clustering

## Expected changes

Add velocity repository/context provider, key builders, and integration/unit tests.

## Implementation checklist

- [x] Use `fraudlatch:velocity:customer:{customer_id}`.
- [x] Use `fraudlatch:velocity:merchant:{merchant_id}`.
- [x] Store event timestamps as Sorted Set scores.
- [x] Remove entries older than five minutes before counting.
- [x] Apply TTL and bounded retention.
- [x] Define zero-history cold-start context.
- [x] Classify Redis unavailability as retryable.

## Interfaces and contracts

The context provider returns counts and timestamps needed by `rules-v1`; it does not calculate a risk score.

## Validation

Test events inside/outside the window, same timestamp, customer/merchant separation, restart behavior, and Redis outage.

## Acceptance criteria

- [x] Velocity uses synthetic `event_time`, not ingestion wall-clock time.
- [x] Expired events do not contribute to counts.
- [x] Cold-start scoring is deterministic.
- [x] Customer/merchant IDs never appear as metric labels.

## Failure and edge cases

Future or naive event times must be rejected or normalized before entering state. Redis failures must prevent false success and trigger queue retry.

## Definition of done

Velocity context is bounded, deterministic, integration-tested, and consumed by rules-v1.

## Follow-up

Integrate context and engine into the worker in Milestone 6.1.
